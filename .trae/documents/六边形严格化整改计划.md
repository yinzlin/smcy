# 六边形严格工程化整改计划

## Context（为什么做）

项目从单 crate 重构为 cargo workspace 后，六边形骨架已立起来（domain 出站端口、application 入站端口、database 实现、backend 装配均已就位），但**依赖规则仍有穿透**，与「严格六边形」不符，无法作为长期深耕的脚手架。

本次目标：把依赖规则收敛到**零例外**，并沉淀为可长期执行的判定标准。用户已确认范围为**全量严格合规**，`*Req` 迁往 `application/dto`。

## 判定标准（Phase 0 产出 ADR）

产出 [`.trae/documents/六边形分层规则.md`](file:///d:/projects/smcy/.trae/documents/)，固化以下规则，作为后续长期开发的判据：

1. **依赖白名单**：`domain`（仅 serde）、`application`（domain+common，**不得** database/sqlx）、`database`（domain+common）、`backend`（application+database+common，**唯一的组合根**）。frontend 经 rust-embed 内嵌，不参与 Rust 依赖图。
2. **持久化访问唯一路径**：任何 hive 层都不得出现 `database::pool()` / `sqlx::`；全局 `pool()` 仅允许出现在 `backend/src/di.rs`。
3. **契约归属**：HTTP 请求体（`*Req`）归 `application/dto`；domain 端口出入参一律用 domain 自有类型（新引入输入结构体，不含 serde）。
4. **`UserCtx` 归属**：保持在 domain（会话上下文是被多域共享的领域概念，非 HTTP 契约）。
5. **错误映射链不变**：`DomainError`(4 变体) → `From` → `UseCaseError`(7 变体) → backend 映射 HTTP 状态；文案逐字节保持。
6. **接口兼容红线**：所有响应/请求 JSON 字段名与顺序不变；冒烟 232 条断言为行为基线。

## 分阶段实施

### Phase 1：中间件端口化（最高优先，闭环样板）

1. `domain/port/user.rs` 新增 `SessionCtxRow{role,supplier_id,purchaser_id}` 与 `session_ctx(id)`（补齐 `get_user_ctx` 缺失的 supplier/purchaser 口径）。
2. `domain/port/sales_order.rs` 新增 `purchaser_id(order_id)`（语义归位；`check_sales_order_access` 用），在 `repo/sales_order.rs` 实现。
3. `database/sqlite/repo/user.rs` 实现 `session_ctx`。
4. 重写 [auth.rs](file:///d:/projects/smcy/crates/backend/src/middleware/auth.rs)：删除 `use sqlx::Row` / `use database::pool`；`get_user_role` 走 `UserRepo`、`get_user_ctx` 走 `session_ctx`、`log_operation` 走 `OperationLogRepo::log`、`check_sales_order_access` 走 `purchaser_id`。函数签名改为接收 repo 参数。
5. `di.rs`：**同一 repo 实例**同时注入服务与 App（App 增加 repo 句柄字段，供中间件使用）。
6. `handlers.rs`：~100 处 `check_api_permission(&headers,..)`/`get_user_ctx(&headers)` 补 `app` 参数（纯机械）。
7. 拦截页文案（"请登录"/"您没有权限访问此页面" 与 layout_html 调用）逐字节不变。

完成标志：`cargo check` 零警告；冒烟 232/232；独立提交。

### Phase 2：application 层去穿透（工作量主体）

按「先删重复、再补新口」两步走：

- **删重复**：`service/price.rs` 12 个自由函数中，凡已被 `PriceScheduleRepo` 覆盖者（`rebuild_price_schedule_end_dates`/`lookup_effective_price`/`batch_lookup_effective_prices`/`lookup_contract_price`/`log_price_change`/`recalc_base_price_by_markup`/`auto_mark_gov_status`/`sync_product_base_price`）**删除**，调用点改为经注入 repo 调用。
  - 调用点：`sales_order.rs`(L88-92/1264/3168)、`product.rs`(L353/366/385/664)、`today_price.rs`(L132-133)、`di.rs`(L120，bootstrap 内构 `SqlitePriceScheduleRepo` 调 `rebuild_end_dates`)。
  - 服务结构体已持 repo（如 [ProductService](file:///d:/projects/smcy/crates/application/src/service/product.rs#L23)）→ 改 `self.repo.*` 即可。
- **补新口**（无现成端口者）：
  - `order_no.rs` `generate_order_no`：新增 `SalesOrderRepo::max_seq_for_date` / `PurchaseOrderRepo::max_seq_for_date`（各 1 实现）。
  - `stock.rs` 13 处：补入 `InventoryRepo`/`QueryStockRepo` 缺的汇总查询方法。
  - `excel.rs` 9 处：`contact_phone`→`UserRepo::get_contact_phone`；订单头/明细/分摊明细→新增 `SalesOrderRepo` 的验收导出查询方法（含商品/类别 JOIN 与 `gov_status`、`shelf_life` 字段）。
  - `purchase_order.rs`(2)/`sales_order.rs`(2)/`order_allocation.rs`(1)/`order_supplement.rs`(1)：逐点归入对应域端口。
- **收依赖**：从 [application/Cargo.toml](file:///d:/projects/smcy/crates/application/Cargo.toml#L10-L11) 移除 `database` 与 `sqlx`；清理 `service/*.rs` 的 `use database::*` / `use sqlx::*`。

完成标志：`grep -n "pool()\|\"sqlx::" crates/application/src` **零命中**；`cargo check` 零警告；冒烟 232/232；独立提交。

### Phase 3：`*Req` 迁往 application/dto

- **迁移**：21 个结构体从 `domain/lib.rs` 移入 `application/src/dto/`（按域分文件，如 `dto/order.rs`）；derive/`#[serde(default)]`/字段名与顺序**逐字保留**。`domain/lib.rs` 只留 `UserCtx`。
- **解耦（关键约束）**：5 个 domain 端口直接以 `*Req` 为出入参 —
  [sales_order.rs](file:///d:/projects/smcy/crates/domain/src/port/sales_order.rs#L329)、[purchase_order.rs](file:///d:/projects/smcy/crates/domain/src/port/purchase_order.rs#L174)、[price_schedule.rs](file:///d:/projects/smcy/crates/domain/src/port/price_schedule.rs#L102)、[order_supplement.rs](file:///d:/projects/smcy/crates/domain/src/port/order_supplement.rs#L126)、[food_accept.rs](file:///d:/projects/smcy/crates/domain/src/port/food_accept.rs#L26) — 因 domain 不得依赖 application，需为这 5 个端口在 **domain 侧引入同名同序的输入结构体**（如 `SalesOrderInput`/`PurchaseOrderInput`/`PriceScheduleInput`/`OrderSupplementInput`/`AcceptInput`，**不派生 Deserialize**），由 application 在收用例入参时把 `dto::*Req` 映射为 `domain::Input`。
- **导入收口**：`handlers.rs` 的 `use domain::*;` 替换为对 `application::dto::*Req` 的精确导入；保留对 domain 非 Req 类型（`UserCtx`、Row 结构体、枚举）的必要导入。
- **入站端口**：`application/port/*` 若以 `*Req` 为入参，改为引用 `application::dto` 的类型（同 crate，合法）。

完成标志：`domain/src` 中 `*Req` 零残留；`domain` 依赖仍仅 `serde`；冒烟 232/232；独立提交。

### Phase 4：长期健康项（脚手架化）

- 把「domain 仅依赖 serde」「application 不依赖 database/sqlx」「非 di.rs 不得出现 pool()」固化为校验脚本（可挂 `make check`）。
- 提供可复现的种子库/密码重置脚本，消除冒烟环境对「本机 super_admin 密码哈希」的隐式依赖。
- 更新 [Rust 全栈项目架构整合方案.md](file:///d:/projects/smcy/.trae/documents/Rust%20全栈项目架构整合方案.md) 中与实况不符的章节（Dioxus/PG/Redis 模板目录已按实际删除），避免文档与脚手架再次漂移。

## 验证

每一步（每个 Phase 每刀）均执行：

1. `cargo check`（workspace 根）——要求零警告。
2. `grep` 断言：`crates/application/src` 无 `pool()`/`sqlx::`；`crates/domain/src` 无 `*Req`；非 `di.rs` 的 backend 无 `pool()`。
3. `cargo build --release`（`x86_64-win7-windows-msvc`），exe 复制回仓库根覆盖旧产物。
4. 隔离目录跑 `scripts/smoke.ps1`，要求 **232/232 全通过**（响应逐字节兼容基线）。
5. 独立提交，遵循 Conventional Commits 混合模式（type 英文 + scope/描述中文）。

## 不做的事

- 不补齐 DDD 战术模式（Aggregate/ValueObject/DomainEvent）——「严格六边形」不等于 DDD 战术模式，不恢复已删的模板空目录。
- 不引入 dyn 抽象、不换数据库、不动前端契约与业务行为。
